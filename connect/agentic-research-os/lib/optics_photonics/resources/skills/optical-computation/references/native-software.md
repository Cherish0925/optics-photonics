# Native software sessions

Use `software_details` to obtain the native adapter's platform, package requirements, options, program example and original API documentation. `discover_native_software(roots=[...])` locates known SDK layouts. `bind_native_software(tool, python, sdk_path, options, threads, concurrency)` selects the interpreter and SDK. Module discovery does not start or verify a licensed solver. Install a bridge package in the selected environment only when needed: COMSOL uses MPh; OpticStudio uses ZOSPy. Lumerical and CST can use their installed vendor Python modules.

Submit through `submit_calculation` or `submit_workflow`. The input `project` is an absolute path on the computing machine. The worker creates a new owned session, opens the source model and saves its working model in OUTPUT_DIR before running the program. All iterations within a program reuse that session. Successful completion saves the model again; normal exit and Python errors release the owned session. Forced process termination may leave a vendor service running outside the worker process tree.

The program receives `SDK`, `SESSION`, `MODEL`, `PROJECT_FILE`, `EXPORT`, `INPUTS`, `OUTPUT_DIR`, and sets `RESULT` to compact JSON. `EXPORT(value, name)` saves arrays and complex values in NPZ and their structure in JSON. Native APIs remain available: COMSOL `MODEL.java`, OpticStudio editors and analyses, Lumerical script methods, CST project/modeler/results. Preserve physical units, coordinate and normalization conventions in the result files.

`inspect_project` opens/saves without solving. `solve_project` supports COMSOL, Lumerical and CST; OpticStudio analyses use a source program. COMSOL accepts `parameters` as names -> values with units, optional `study`, and `results` as expressions. Lumerical accepts `parameters` as object -> property -> value, and `results` as [{monitor, quantity}]. CST accepts `results` as native result-tree paths; geometry and parameter changes use a source program and the installed API. Read project-specific names rather than inventing monitor paths or expressions.

Lumerical options: `module` (lumapi or ansys.lumerical.core), `product` (FDTD, MODE, DEVICE, INTERCONNECT), `hide`. COMSOL option: `version`. OpticStudio options: `opticstudio_directory` or `zosapi_nethelper`, not both. Its session runs in standalone mode on Windows. Remote Agents can launch the MCP server over SSH on that workstation. Keep project dependencies accessible at their expected paths.

COMSOL and Lumerical receive the selected thread count; CST and OpticStudio use their native CPU settings. Per-tool concurrency is shared across background jobs. Begin with concurrency 1 for licensed sessions, then set it to the installed license and machine capacity.
