# 光学数字实验室：开发接力

[English](DEVELOPMENT.md) · [参与开发](../CONTRIBUTING.md) · [运行机制](EXECUTION.md)

目标是让研究者和 Agent 连接实际计算环境，运行完整的光学与光子学研究程序，组合不同软件，持续取得可解释、可继续使用的科学结果。Optics-Photonics-AI-Lab 独立安装、运行和发布。

| OP-12 | 已完成 episode 索引、重试与改变进程数后的续接、单独记录求解错误 | 共享数据集及异步学习器集成 |

## 接下来做什么

优先 **OP-05**：让软件接入包可以独立分发。基于 OP-04 数据接口和第一条 OP-08 数据交换，继续扩展 **OP-07/08** 的跨软件研究流程。有许可证工作站的伙伴推进 **OP-06**，有远端计算资源的伙伴推进 **OP-09/10**。下文保留工作编号，方便协作。

## 一、执行与数据

### OP-01 · MCP 请求并发

0.6.0 已实现：有数量上限的并发调用、独立的状态等待、完整响应写入、请求取消，以及断开连接后继续已提交的计算。TypeScript 支持 AbortSignal。入口：[mcp.py](../src/optics_photonics/mcp.py)、[客户端](../clients/typescript/src/index.ts)。

### OP-02 · 大工作流调度

0.6.0 已实现：进程保留就绪队列与依赖状态，增量读取追加步骤，调度时不读取已完成步骤的结果。CPU 与命名资源仍由所有运行共享。后续分别记录 SQL、进程启动、求解器耗时，再决定是否引入常驻计算进程。入口：[jobs.py](../src/optics_photonics/jobs.py)。

### OP-03 · 大文件与数组访问

0.6.0 按目录逐层读取，只为返回页面读取文件大小与数组信息；prefix 可选单个步骤，统计总数仍需遍历匹配文件名。继续增加持久结果文件索引，兼容旧运行和计算中新增的文件。文件引用采用运行、步骤、尝试及相对路径，避免跨机器依赖绝对路径。

在现有字节读取之外提供数值数组切片、指定通道与适量降采样。NPY 可先用内存映射；分块格式按实际求解器输出增加。下游步骤按引用访问输入文件，远端下载传送文件内容到客户端，不能仅返回服务器本地路径。

交付：大量文件翻页、部分写入中的文件和超出内存容量的数据集仍能按需访问；返回规模由请求决定。

起点：[jobs.py](../src/optics_photonics/jobs.py)、[native.export](../src/optics_photonics/native.py)、[mcp.py](../src/optics_photonics/mcp.py)。依赖 OP-01 的并发处理；数组说明与 OP-04 对齐。

### OP-04 · 科学数据说明

0.7.0 已实现：`data.quantity`、`data.save`、`data.load` 用 NPZ 数组与配套 JSON 说明交换数据。坐标可以是同文件中的数组、均匀采样或通道／端口标签。`read_array` 返回与切片、倒序和降采样数值对应的说明与坐标，连接器无需安装 NumPy。

单位与光谱量转换、复振幅时间约定及波前正负号转换均显式进行并保留来源；光谱量转换同时更新物理量名称。归一化、参考面、材料来源按实际需要记录；不要求普通数组和标量结果额外附带说明。

[HCIPy → POPPY 示例](../examples/exchange/) 保存带像差的光瞳，转换光程差符号与单位，得到一致的像点偏移和 Strehl 比。网格、光线、密度矩阵及其他软件继续沿用同一机制扩展。实现：[data.py](../src/optics_photonics/data.py)、[arrays.py](../src/optics_photonics/arrays.py)。

## 二、软件与研究能力

### OP-05 · 可独立安装的软件接入包

保留 `register_software`、`bind_environment`、完整程序与命令行入口。让接入包共同携带软件身份、版本要求、支持的平台、安装来源、能力说明、可运行程序和领域资料；安装包可以位于目录之外。

安装、选择解释器、连接 SDK、打开会话和实际求解分别报告状态。缺少的配置一次性列出，已有可用环境直接复用。按需安装科学依赖，升级连接器保留环境与历史运行。

交付：第三方新增一个 Python 库、一个原生命令程序和一个 SDK 软件，无需修改核心分发代码；安装、发现、更新、卸载接入包的行为清晰。

起点：[environments.py](../src/optics_photonics/environments.py)、[catalogue.py](../src/optics_photonics/catalogue.py)、[packages.py](../src/optics_photonics/packages.py)、[connections.json](../data/connections.json)。

### OP-06 · 原生软件完整研究流程

分别完成 COMSOL、Lumerical、OpticStudio、CST 的项目载入或建模、参数修改、求解或分析、结果提取、模型保存、会话退出。每个软件独立 PR；继续保留原生 API，不用少量封装动作限制专业操作。

优先处理会话重复启动、版本差异、许可证释放及中途中断后的项目恢复。工作站实际运行记录注明软件版本、平台和执行的操作；社区包装库与厂商 SDK 分别标明来源。

交付：一个真实研究程序能连续修改、计算、保存和再次载入模型；两个独立运行使用各自输出，关闭 Agent 后仍可取回结果。根据实际过程改善适配器，不将四个软件的行为强行写成同一套命令。

起点：[native.py](../src/optics_photonics/native.py)、[native examples](../examples/native/)、[NATIVE.md](NATIVE.md)。可与 OP-05 并行，数据输出逐步采用 OP-04。

### OP-07 · 开放软件研究能力

从当前 16 个库的计算入口扩展到完整程序，并接入现有目录中尚无完整运行路径的软件。按下表组织任务；示例工具不是封闭支持名单，新工具沿用 OP-05。

| 研究对象 | 可先开展的程序与接入 |
| --- | --- |
| 几何光学、照明 | Optiland / Raysect：真实光线、非序列传播、系统优化 |
| 衍射、成像、偏振 | HCIPy / POPPY / LightPipes / py-pol：复场、像差、PSF/OTF、偏振与重建 |
| 薄膜、材料、散射 | TMM / Mie：色散、吸收、角度/波长变化、材料数据来源 |
| Maxwell、周期结构、模式 | Meep / MPB / grcwa / legume：网格、边界、激励、模式、场与通量 |
| 集成光子学 | gdsfactory / KLayout / SAX：版图、器件端口、S 参数与电路 |
| 光纤、脉冲、激光、谐振腔 | 对应目录中的传播与腔体软件：复包络、色散、非线性、增益与噪声 |
| 量子光学 | QuTiP：开放系统、耗散、相关函数与测量结果 |
| 生物光学、X 射线、反问题 | 对应目录中的输运、束线与重建工具：几何、源、材料和可观测量 |

交付：每个接入包含环境准备、参数化研究程序、科学输出、使用方法及其适用条件。依任务选择解析极限、收敛变化或另一种方法比较结果；增加软件条目不能代替完成计算流程。

### OP-08 · 跨软件研究程序

0.7.0 已用 HCIPy 和 POPPY 实现场／像差到 PSF 的路径，从 [steps.json](../examples/exchange/steps.json) 启动。其他两条路径继续开发：周期结构的复透反射到有限器件传播，以及版图到器件 S 参数再到电路响应。

每个转换明确物理近似、单位、采样、相位和参考面。参数、几何与材料可以替换，不把一个算例写死成唯一研究任务。

交付：用户从一个参数文件启动计算，获得各阶段结果及最终研究量，并能替换其中一个软件。依赖 OP-03、OP-04 和相关 OP-06/07 接入。

## 三、持续计算与学习

### OP-09 · 远程与集群任务接续

当前可通过 SSH 启动 MCP；远程求解器任务编号仍由用户程序自行保存。增加持久的后端、任务编号、状态和结果位置，让提交、连接已有任务、查询、取消和下载共享现有运行接口。

先选择 Slurm 与 Tidy3D 两种不同执行方式。连接中断后查询已有任务；提交响应丢失时，根据服务端支持的标识查找任务，没有依据时保留提交结果未知，避免自动重复提交。网络连接中断与远端求解失败分别记录。

交付：重启连接器后继续跟踪原任务，结果可取回，取消作用于实际远端任务。用已有计算账户运行；没有远端条件时如实标明已完成的本地部分。

参考：[Slurm API](https://slurm.schedmd.com/rest_api.html)、[Tidy3D jobs](https://docs.flexcompute.com/projects/tidy3d/en/latest/api/submit_simulations.html)。依赖 OP-03、OP-05，并与 OP-10 共用资源说明。

### OP-10 · 资源配置落实到求解器

现有 `cpu`、`requirements`、`pools` 是本机共享额度，部分适配器已传递线程数。补齐它们与求解器线程、MPI ranks、GPU 设备和远端队列的明确对应，保存最终启动配置。

许可证容量来自工作站配置或支持查询的许可服务，分别说明额度来源和真实许可可用性。资源暂不可用时保留任务与原因。已运行任务的结束状态由相应后端确认。

交付：同一机器的多个研究任务实际遵守线程、GPU 与软件并发设置；连接到外部调度器时由该调度器分配集群资源。

起点：[jobs.resources](../src/optics_photonics/jobs.py)、[environments.bind](../src/optics_photonics/environments.py)、[native.session](../src/optics_photonics/native.py)。

### OP-11 · 长程序内部继续运行

`resume_run` 当前保留成功步骤，重跑未完成步骤。增加可选的进度与保存点接口，让大扫描、优化和长求解程序保存已完成部分。求解器支持恢复时载入其状态；不支持时从明确的程序步骤继续。

恢复信息包括程序版本、输入、完成位置和所需模型文件。远端任务采用 OP-09 的重新连接；本地活会话继续留在研究进程内，不能把所有 SDK 对象当作可序列化状态。

交付：一个长扫描中断后保留已完成参数点，并继续剩余计算；重复请求不重复提交已有工作。依赖 OP-03，输出说明采用 OP-04。

### OP-12 · Episode 续接与数据组织

0.6.0 已按 episode 保存完成索引，重试或改变进程数后的续接不会重复采集已完成的 episode。继续完善共享数据集的尝试选择，保留中断记录；科学程序变化通过 task 与 policy 版本表达。

继续使用 `terminated` / `truncated` 与最后观测。采集失败、求解失败和科学任务的负奖励分别表达。允许接入不同物理模型、动作空间和观测形式。

交付：中断后更换 worker 数继续采样，已完成 episode 不重复计入数据集；轨迹可按任务、策略版本、episode 与尝试读取。依赖 OP-03、OP-11。

### OP-13 · 并行采样与学习器连接

在 OP-12 之上支持异步 episode 分配、容量受限的数据传递和策略更新。数值循环留在科学计算进程，不为每个动作调用 MCP。分别提供轻量 CPU 环境、较重全波计算和长会话三类运行方式。

交付：实际连接一个学习器完成采样与策略更新，记录 worker 数、episode 时长分布、采样吞吐、等待时间和资源占用。先完成单机，再通过 OP-09 扩展多机；训练算法由学习框架负责。

## 协作与交付

每位开发者从最新主分支建立独立分支，先查看打开的 PR 和相关分支。一个 PR 围绕一项可用行为，说明改变了什么、如何使用、在哪个环境运行过及尚需哪个外部环境。OP 编号用于交接，不要求一项必须限制为一个 PR。

OP-01、02、03、09、11 经常涉及同一执行代码，先说明接口变化再分工；OP-05、06、07、15、16 可分别由不同伙伴推进。保持原有项目名、软件 ID、工具调用和数据可继续使用；格式改变提供明确的读取与迁移方式。保留贡献者归属。

TypeScript 负责宿主与客户端，Rust 负责原生进程，Python 连接科学软件与程序，SQL 保留任务及资源。根据实际性能结果调整实现位置。

源文件修改后使用仓库已有的相应运行流程；涉及内置插件时重新生成，发布由维护者统一安排。文档用具体操作、数据与结果说明功能。
