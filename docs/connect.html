02 / OPTICS & PHOTONICS

Use the scientific environment you need.

The connector runs on Windows, macOS and Linux with Python 3.10+. Each solver keeps its own platform and license requirements.

python -m pip install "git+https://github.com/Cherish0925/optics-photonics.git@optics-v0.1.0"
optics-photonics info tmm
optics-photonics prepare tmm

Save these inputs as inputs.json. The calculation returns a compact result and a spectrum CSV.

{
  "n": [
    1,
    1.45,
    1.52
  ],
  "thickness_nm": [
    100
  ],
  "wavelength_nm": [
    450,
    550,
    650
  ],
  "polarization": "s",
  "angle_deg": 0
}
optics-photonics run tmm spectrum --inputs @inputs.json

Reuse an installed environment

optics-photonics bind tmm --python /path/to/python --threads 1 --concurrency 4
optics-photonics environments

Use a release wheel when Git is unavailable. Prepare creates an isolated environment only for listed recipes; commercial tools, MPI builds and GPU distributions use their own installers. Configuration is kept under OPTICS_HOME or ~/.optics-photonics.

Install once, keep environments

New connector versions produce a new plugin directory. The host updates its installed package; software environments and saved experiments remain separate.

Local and remote execution

Local MCP uses a Python process. Remote Agents communicate with IOP on the computing host. Cloud-only hosts need their own execution environment or bridge.

Host-native configurations are supplied. Package install/update was exercised with Research OS; real MCP calls were exercised with IOP. Full GUI behavior is not claimed for every Harness edition.

06 / OPTICS & PHOTONICS

Calculations continue with IOP.

Submit a complete program or a dependency graph. IOP owns the running calculation; an Agent can disconnect and return to the same experiment.

optics-photonics attach tmm
optics-photonics submit tmm --program research.py --inputs @inputs.json --request-id study-001
optics-photonics status RUN_ID
optics-photonics files RUN_ID
optics-photonics download ARTIFACT_ID spectrum.csv

Native program

INPUTS supplies JSON parameters. OUTPUT_DIR stores arrays and models. RESULT returns compact JSON.

Parallel and sequential

Explicit after: [] permits independent work. Dependencies set order; IOP bindings transfer results. Use one program for a live solver session.

Resources

Threads and process concurrency are configured per environment. MPI, GPUs, licenses and clusters use the solver’s real launch configuration.

Scientific records

Inputs, source, software versions, compact results and native data files stay together. Physical measurements and digital calculations can share an IOP experiment.

IOP 0.8.5 indexes command files at workflow completion. For early access during a continuous experiment, use explicit artifact upload. Persist remote solver job IDs and resume through the provider API.
