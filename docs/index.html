01 / THE LANDSCAPE

Start with the physics

An optical experiment can involve geometry, complex fields, device ports, quantum states and detector models. Their physical quantities and conventions connect the software.

01
CHOOSING A MODEL

Does the model represent the effect?

Rays describe many macroscopic systems; diffraction needs complex fields; subwavelength devices often require full-wave methods; quantum correlations need quantum states.

PROGRAMMABLE ACCESS

APIs and scripts execute the work

LLMs can write programs that call existing solvers. MCP exposes retrieval or execution tools; Skills provide working knowledge. A Python library can be useful to an agent without a dedicated MCP.

LICENSING & SERVICES

Separate software, models and services

An open client, free local features, a paid solver and a restricted PDK can coexist. Downloadable, source-available and free describe different conditions.

FROM SIMULATION TO A DIGITAL TWIN

A digital twin stays tied to a real system

A simulator provides a forward model; measurements constrain its parameters to the real instrument; a surrogate accelerates evaluation within a defined domain. They serve complementary roles.

y = F(θ, u) + ε   ·   F̂ ≈ F

θ: geometry, materials, calibration and noise; u: inputs and controls; y: observations. Data and validation determine the valid domain of the surrogate F̂.

  1. System & stateIdentify the instrument, geometry revision, materials and operating conditions.
  2. Physics & observationTransform solver outputs into quantities the actual detector measures.
  3. Calibration & updatesEstimate parameters and biases from data, preserving uncertainty and validity conditions.
  4. Surrogates & optimizationExplore with low-cost models within their valid domains, then check important candidates with physics or experiments.

Symbolic to numerical · SymPyPython ＋

Derive the thin-lens and free-space ABCD relation, then generate a numerical function.

import sympy as sp

z, f = sp.symbols("z f", real=True, nonzero=True)
P = sp.Matrix([[1, z], [0, 1]])
L = sp.Matrix([[1, 0], [-1/f, 1]])
M = sp.simplify(P * L)
M_numeric = sp.lambdify((z, f), M, "numpy")
print(M_numeric(0.10, 0.05))  # Both z and f are in meters

The static files need no server API or account. Read stable IDs and the review date; retrieve the linked documentation before choosing installation or solver parameters.

import json, urllib.request
url = "https://raw.githubusercontent.com/Cherish0925/optics-photonics/main/data/catalogue.en.json"
tools = json.load(urllib.request.urlopen(url))
candidates = [t for t in tools if t["group"] == "open"
              and "periodic" in t["cats"] and t["route"] == "api"]
for t in candidates:
    print(t["id"], t["name"], t["api"], t["sources"])

Scope, sources and interpretation

08

Coverage

Covers major optical methods and engineering tasks, with supporting algebra, materials, geometry and image tools.96 entries count tools and product families; this is not an exhaustive inventory of every optical software package.Solver modules within a product family are not counted as separate products.

Entries have identifiable documentation, code, product or methods sources. Commercial applications, established research tools and emerging implementations retain their distinct roles; not every entry is claimed to be widely used in both academia and industry.

This is a software-selection and interface study. Application evidence is recorded per entry; suitability for a particular instrument needs relevant benchmarks and measurements.

Source methodology

Reviewed: 2026-10-20.Product and interface claims prioritize vendor documentation. Open-source entries use maintainer repositories, licenses, author documentation or institutional sources. Every entry preserves primary-source links.

Official and community MCP / Skill implementations are distinguished. A located source is not production certification; unverified does not mean absent. Third-party bridges are not presented as official vendor APIs.

Groups reflect software licensing and execution conditions. Open source still needs computing resources; purchased academic licenses remain commercial. Prices vary by modules, seats and compute, so no universal prices are invented.
